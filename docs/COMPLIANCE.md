# ForgeISO Compliance Mapping

Mapping of ForgeISO's enforced controls to common external audit frameworks.
Use this when a customer or auditor asks "what does ForgeISO do for control X?"
or when planning what to add for a new framework.

This is **not** a certification. It is a self-attestation of the controls that
are implemented in code, CI, and process. An external auditor's findings
override anything here.

## Frameworks covered

- **NIST SP 800-53 Rev. 5** — selected controls relevant to a build tool that
  produces installer artifacts
- **CIS Critical Security Controls v8** — IG1 baseline
- **SOC 2 Type II** — Common Criteria + Availability category

## NIST 800-53 mapping

| Control | Title | ForgeISO implementation |
|---|---|---|
| **AU-2** | Event Logging | Structured JSON tracing across CLI/TUI/GUI, daily-rolling files at `<FORGEISO_LOG_DIR or $XDG_STATE_HOME/forgeiso>/forgeiso.log.<date>`. See `docs/RUNBOOKS.md`. |
| **AU-9** | Protection of Audit Information | Logs are written to user-owned dirs with default permissions; no privileged escalation. Log rotation handles retention. |
| **AU-12** | Audit Record Generation | Every engine operation emits structured events via `EngineEvent`; subscribed by all three frontends. |
| **CM-2** | Baseline Configuration | `tests/baseline-perf.json` records the performance baseline; ADRs in `docs/adr/` record load-bearing architectural decisions. |
| **CM-3** | Configuration Change Control | Git-tracked. Conventional commits. ADRs required for load-bearing changes. CI gate (`scripts/s-tier-audit.sh`). |
| **CM-6** | Configuration Settings | Default settings in `engine/src/config/inject.rs` (`InjectConfig::default()`). Override via CLI flags or GUI form. |
| **CP-9** | System Backup | Form state persisted at `$XDG_DATA_HOME/forgeiso/slint-state.json` excluding passwords (`#[serde(skip)]`). |
| **CP-10** | System Recovery & Reconstitution | `forgeiso-desktop` restores form state on next launch from persisted JSON. |
| **IA-5** | Authenticator Management | Passwords entered in GUI never persist (`#[serde(skip)]` on InjectState.password / encrypt_passphrase). |
| **RA-5** | Vulnerability Monitoring | CI runs `cargo audit` + `cargo deny` + `gitleaks` + `Trivy fs scan` on every PR (`.github/workflows/ci-rust.yml` security job). |
| **SA-11** | Developer Testing & Evaluation | 670+ tests, ≥40% workspace coverage gate (`tarpaulin.toml`), criterion benches with regression gate (`scripts/perf-bench.sh`). |
| **SA-15** | Development Process | Conventional commits + 5 ADRs + RUNBOOKS + criterion benches + tarpaulin gate. |
| **SC-12** | Cryptographic Key Establishment | SHA-256 ISO content verification (engine `sha256_file`); GUI never stores LUKS passphrase to disk. |
| **SC-28** | Protection of Information at Rest | Form state persisted JSON has 0600 mode (inherited from process umask); passwords excluded. |
| **SI-7** | Software, Firmware, and Information Integrity | SHA-256 verification of source ISO and output ISO; ISO-9660 compliance check via `forgeiso check`. |
| **SI-10** | Information Input Validation | Engine `EngineError::PathSafety` (E050) rejects path-traversal in source/output paths. CLI clap derive validation. |

## CIS Controls v8 mapping (IG1)

| Control | Implementation |
|---|---|
| **CIS 1** Inventory of Enterprise Assets | N/A — ForgeISO produces installer media; asset inventory is the customer's. |
| **CIS 2** Inventory of Software Assets | SBOM (CycloneDX 1.5) generated by syft in CI on main, attached to releases. |
| **CIS 3** Data Protection | See SC-28 above. Passwords never written to disk. |
| **CIS 7** Continuous Vulnerability Management | See RA-5 above. cargo audit + cargo deny + Trivy on every PR. |
| **CIS 8** Audit Log Management | See AU-2/AU-9/AU-12 above. |
| **CIS 16** Application Software Security | See SA-11/SA-15 above. |

## Trigger phrases

Use this document when responding to:
- "Is ForgeISO SOC2 ready?"  → Show this table; explain self-attestation vs certification.
- "What logging does ForgeISO do?"  → AU-2 row + docs/RUNBOOKS.md.
- "How do you verify integrity?"  → SI-7 row + SHA-256 verify + ISO-9660 check.
- "Where are passwords stored?"  → IA-5 + SC-28 rows: never.

## How to add a control

1. Pick a framework + control number.
2. Find or create the implementation in code/CI/docs.
3. Add a row above pointing at the artifact.
4. If the implementation needs to change, write an ADR first.
