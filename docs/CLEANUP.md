# Artifact Cleanup

`scripts/cleanup-artifacts.sh` removes generated artifacts that grow during
development. It is idempotent (re-running on a clean tree exits 0 with no
work) and never touches source files, `target/debug/`, or `target/release/`,
so cargo's incremental compile cache stays warm.

## Modes

### `scripts/cleanup-artifacts.sh` (default)

Removes artifact directories that are local-only and trivially regenerable:

| Path                              | What it is                                                | Regenerated by              |
| --------------------------------- | --------------------------------------------------------- | --------------------------- |
| `dist/`                           | release tarballs, perf-bench JSON, SBOM output            | `scripts/release/*`, `scripts/perf-bench.sh` |
| `mutants.out/`                    | last cargo-mutants run                                    | `scripts/run-mutants.sh`    |
| `mutants-fullrun.out/`            | full-run cargo-mutants profile                            | `scripts/run-mutants.sh`    |
| `target/criterion/`               | criterion benchmark HTML reports                          | `cargo bench`               |
| `target/tarpaulin/`               | coverage HTML                                             | `cargo tarpaulin`           |
| `forgeiso-cache/`                 | regtest extract/inject working dir                        | regression tests            |
| `forgeiso-regtest/`               | regtest output ISO(s)                                     | regression tests            |
| `tests/test-builds/*`             | Phase 9a release-test ISOs (preserves `.gitignore`)       | `scripts/test-releases.sh`  |

`target/debug/`, `target/release/`, and the rest of `target/` are intentionally
preserved. Wiping them would force a full rebuild on the next `cargo` invocation.

### `scripts/cleanup-artifacts.sh --aggressive`

Everything in default mode, plus:

| Path                  | What it is                                              | Regenerated by    |
| --------------------- | ------------------------------------------------------- | ----------------- |
| `~/.cache/forgeiso/`  | engine-side cache of downloaded source ISOs (≥100 GB)  | the next `forgeiso build` (re-downloads from upstream) |

Use aggressive mode when:

* you are reclaiming significant disk space and are okay re-downloading
  upstream installer ISOs (Ubuntu, Fedora, Rocky, AlmaLinux, Arch, …) on the
  next build,
* a corrupt or stale cache entry is causing bogus build failures,
* you are about to archive or move the workstation.

Default mode is the right choice between routine test cycles.

### `scripts/cleanup-artifacts.sh --dry-run`

Lists what would be removed and how much disk space would be freed; no
filesystem changes. Combine with `--aggressive` to preview an aggressive
clean:

```bash
scripts/cleanup-artifacts.sh --dry-run
scripts/cleanup-artifacts.sh --aggressive --dry-run
```

`--dry-run` always exits 0.

## Output

Each path that is removed (or would be removed) prints item count and freed
bytes; a summary line totals across all paths. When the tree is already clean
the script prints `nothing to do (already clean)` and exits 0.

```text
cleanup-artifacts: default mode — repo: /home/jalsarraf/git/ForgeISO
  removed dist /home/jalsarraf/git/ForgeISO/dist (109 items, freed 313.3 MB)
  removed forgeiso-regtest /home/jalsarraf/git/ForgeISO/forgeiso-regtest (2 items, freed 4.4 GB)
  …
cleanup-artifacts: removed 3799 items, freed 18.0 GB
```

## Integration as a post-test-releases hook

After `scripts/test-releases.sh` (Phase 9a) finishes, the `tests/test-builds/`
directory typically holds large output ISOs that are no longer needed. Wire
cleanup as a post-step:

```bash
scripts/test-releases.sh
scripts/cleanup-artifacts.sh   # default — removes tests/test-builds/* and friends
```

Or as a one-liner that always cleans up, even on failure:

```bash
trap 'scripts/cleanup-artifacts.sh' EXIT
scripts/test-releases.sh
```

For nightly disk-pressure relief on the runner fleet, an aggressive sweep can
be scheduled via systemd-user timer or cron:

```bash
0 4 * * * cd ~/git/ForgeISO && scripts/cleanup-artifacts.sh --aggressive >> /mnt/nvmeINT/logs/forgeiso-cleanup.log 2>&1
```

## Exit codes

| Code | Meaning                                        |
| ---- | ---------------------------------------------- |
| 0    | Cleanup completed (or nothing to do).          |
| 2    | Invalid argument.                              |

## Safety notes

* Resolves the repo root from the script's own location, so it is safe to
  invoke from any CWD.
* Only removes paths under the repo root, except for `~/.cache/forgeiso/`
  in `--aggressive` mode.
* Never touches `target/debug/`, `target/release/`, `target/doc/`,
  `target/.rustc_info.json`, or any other cargo build state.
* Never touches source-controlled files. `tests/test-builds/.gitignore` is
  preserved so the directory stays version-controlled even after a wipe.
