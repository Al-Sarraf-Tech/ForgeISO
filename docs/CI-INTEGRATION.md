# ForgeISO CI Integration Notes

`.github/workflows/ci-rust.yml` is generated by `haskell-ci-orchestrator` and
carries a `# Generated by haskell-ci-orchestrator — DO NOT EDIT MANUALLY`
header. This document records the additions ForgeISO needs the orchestrator
config to grow before the S+ rubric is fully satisfied.

The repo-side scripts already exist and are operator-runnable via the
`scripts/` directory. The orchestrator config update wires them into CI.

## Required orchestrator additions

### 1. perf-bench job

Add a job that runs after `test` and gates on the criterion baseline:

```yaml
perf:
  name: Perf Regression Gate
  runs-on: [self-hosted, rust-slim]
  needs: test
  timeout-minutes: 30
  steps:
    - name: Checkout
      uses: actions/checkout@v4
    - name: Cache cargo registry
      uses: actions/cache@v4
      with:
        key: ${{ runner.os }}-cargo-registry-${{ hashFiles('**/Cargo.lock') }}
        path: ~/.cargo/registry
        restore-keys: ${{ runner.os }}-cargo-registry-
    - name: Cache target
      uses: actions/cache@v4
      with:
        key: ${{ runner.os }}-cargo-target-${{ hashFiles('**/Cargo.lock') }}
        path: target
        restore-keys: ${{ runner.os }}-cargo-target-
    - name: Run perf benches and compare to baseline
      shell: bash
      timeout-minutes: 25
      env:
        PERF_THRESHOLD: "15"
      run: |
        scripts/perf-bench.sh bench
        scripts/perf-bench.sh compare
    - name: Upload perf results
      if: always()
      uses: actions/upload-artifact@v4
      with:
        name: perf-current
        path: dist/perf-current.json
        retention-days: 30
```

Compare-mode is no-op until `tests/baseline-perf.json` is populated via
`scripts/perf-bench.sh capture` after the engine refactor settles. The job
will pass-through with a "no baseline" notice in the meantime.

### 2. mutation job (nightly)

Mutation testing is too slow for per-PR (~30-60 min). Run nightly:

```yaml
mutation:
  name: Mutation Testing (nightly)
  runs-on: [self-hosted, rust-slim]
  if: github.event.schedule == '0 4 * * 1'   # use existing weekly cron
  timeout-minutes: 90
  steps:
    - name: Checkout
      uses: actions/checkout@v4
    - name: Install cargo-mutants
      shell: bash
      run: |
        if ! command -v cargo-mutants >/dev/null; then
          cargo install cargo-mutants --locked
        fi
    - name: Run mutation tests
      shell: bash
      timeout-minutes: 75
      run: scripts/run-mutants.sh
    - name: Upload mutants report
      if: always()
      uses: actions/upload-artifact@v4
      with:
        name: mutants-out
        path: mutants.out/
        retention-days: 30
```

### 3. contract job

Cheap to run per-PR:

```yaml
contract:
  name: Public API Contract
  runs-on: [self-hosted, rust-slim]
  needs: test
  timeout-minutes: 15
  steps:
    - name: Checkout
      uses: actions/checkout@v4
    - name: Install cargo-public-api + nightly toolchain
      shell: bash
      run: |
        if ! command -v cargo-public-api >/dev/null; then
          cargo install cargo-public-api --locked
        fi
        rustup toolchain install nightly --profile minimal
    - name: Run contract test
      shell: bash
      env:
        FORGEISO_RUN_API_CONTRACT: "1"
      run: cargo test -p forgeiso-engine --test api_contract
```

### 4. release-sign job (release-tag only)

Sign every release artifact (binaries, packages, checksums, SBOM) with cosign
keyless OIDC, then verify the signatures before the release is announced. This
is the desktop-tool equivalent of SLSA L3+ build provenance — the canonical
SLSA tooling (`actions/attest-build-provenance`) is banned per CLAUDE.md
absolute, so we use cosign sign-blob + Sigstore transparency log instead. See
`docs/SECURITY.md` and ADR 0010 for the full security contract.

The job needs `id-token: write` permission so cosign can trade the GitHub
Actions OIDC token at Fulcio for a short-lived signing certificate.

```yaml
release-sign:
  name: Release Sign
  runs-on: [self-hosted, rust-slim]
  if: startsWith(github.ref, 'refs/tags/')
  needs: release
  permissions:
    id-token: write
    contents: write
  timeout-minutes: 30
  steps:
    - name: Checkout
      uses: actions/checkout@v4
    - name: Install cosign
      shell: bash
      run: |
        if ! command -v cosign >/dev/null; then
          curl -sfLo /tmp/cosign https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64
          install -m 0755 /tmp/cosign /usr/local/bin/cosign
        fi
        cosign version
    - name: Download release artifacts
      uses: actions/download-artifact@v4
      with:
        name: release-assets
        path: release-assets/
    - name: Sign release artifacts (cosign keyless)
      shell: bash
      timeout-minutes: 15
      env:
        REL_DIR: release-assets/
        SIG_DIR: release-assets/signatures/
      run: scripts/sign-release.sh
    - name: Verify signatures (round-trip check)
      shell: bash
      timeout-minutes: 10
      env:
        REL_DIR: release-assets/
        SIG_DIR: release-assets/signatures/
      run: scripts/verify-release.sh
    - name: Upload signatures to release
      uses: softprops/action-gh-release@153bb8e04406b158c6c84fc1615b65b24149a1fe
      with:
        files: release-assets/signatures/*
      env:
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Caveats for the orchestrator config:

- The `id-token: write` permission is mandatory for keyless cosign. Without
  it cosign falls back to interactive browser OIDC, which fails in CI.
- The job depends on Sigstore Fulcio + Rekor reachability from the runner
  network. Add an outbound allow for `fulcio.sigstore.dev` and
  `rekor.sigstore.dev` if the runner egress is restricted.
- `actions/attest-build-provenance` MUST NOT be added by the orchestrator
  here or anywhere — it is banned by CLAUDE.md absolute.

### 5. s-tier-audit job (release-tag only)

```yaml
s-tier-audit:
  name: S+ Audit
  runs-on: [self-hosted, rust-slim]
  if: startsWith(github.ref, 'refs/tags/v')
  timeout-minutes: 60
  needs: [test, security, perf, contract, release-sign]
  steps:
    - name: Checkout
      uses: actions/checkout@v4
    - name: Run full audit
      shell: bash
      run: scripts/s-tier-audit.sh
```

## Why these aren't in `ci-rust.yml` yet

`ci-rust.yml` regenerates from orchestrator config. Hand-edits would be
silently overwritten on the next regeneration. The right place to add
these jobs is the orchestrator's per-repo config (likely in
`Al-Sarraf-Tech/.gha-runners` or the orchestrator's own repo).

Until the orchestrator picks them up, every script is operator-runnable
and `scripts/s-tier-audit.sh` is the single-command entry point.

## Operator-runnable equivalents (today, no CI config needed)

```bash
# Full audit (slow):
scripts/s-tier-audit.sh

# Pre-commit (fast — skips coverage, build, perf):
scripts/s-tier-audit.sh --fast

# Just perf:
scripts/perf-bench.sh bench && scripts/perf-bench.sh compare

# Just mutation (background it; takes 30-60 min):
scripts/run-mutants.sh &

# Just contract:
FORGEISO_RUN_API_CONTRACT=1 cargo test -p forgeiso-engine --test api_contract

# Sign release artifacts (after building release-assets/ via scripts/release/make-packages.sh):
scripts/sign-release.sh

# Verify the signatures:
scripts/verify-release.sh
```
